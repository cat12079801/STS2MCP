# v0.113.0 対応（sts2 Issue #823）

調査対象はインストール済みの `v0.113.0` / `16ac0fe3`。
以下の出典はデコンパイル `sts2-d009478a`、比較元は `sts2-9cb4f1ad`。
DLL の参照先を新版にしてビルドする対応であり、旧版向けのバイナリ互換性は保証しない。

## ショップ

`MerchantRoom.GetLocalInventory()` は
`RunManager.Instance.MerchantSynchronizer.GetLocalInventory()` に移った。
購入も `MerchantEntry.OnTryPurchaseWrapper()` から
`MerchantSynchronizer.PurchaseLocalEntry(entry)` を呼ぶようにした。
`MerchantSynchronizer` が購入メッセージ、在庫内 Id による解決、購入中の排他を担当する。
非同期の `Task<bool>` なので、完了済みの false・例外・キャンセルをエラーにし、
未完了なら受付を返して結果を観測する。除去やレリックによる選択待ちがあるため
メインスレッドで Task の完了を待ってはいけない。
`purchase_completed` はアクション実行時点の判定であり、`wait` 後の完了保証ではない。

偽商人は `Models.Events/FakeMerchant.BeforeEventStarted()` で
`Inventory.Setup()` → `MerchantSynchronizer.SetMerchantInventory(Owner, Inventory)` を呼ぶ。
`Entities.Merchant/MerchantInventory.Setup()` は `AllEntries` の順に `Id = (uint)i` を付与する。
偽商人の全商品も登録済み Id を持つため、通常商人と同じ購入 API でよい。
`AllEntries` の通常商品の順番（カード・レリック・ポーション・除去）は従来の index と一致する。
ポーション売却は `ExecuteSellPotion` のままで、今回置き換える購入 API を使わない。

## 多段プレビュー

`Localization.DynamicVars/HitCountVar` の標準名は `HitCount`。
`CalculatedHitCountVar.UpdateCardPreview()` は計算した回数に
`Hook.ModifyAttackHitCount` を適用し、`PreviewValue` に入れる。
MOD は従来どおり対象ごとにプレビューを更新し、その値を読む。

| カード（`Models.Cards`） | 新版の変数 | 回数 |
|---|---|---|
| TwinStrike（ツインストライク） | `HitCountVar(2)` | 2 |
| SwordBoomerang（ソードブーメラン） | `HitCountVar(3)` | 3、強化時 4 |
| TearAsunder（八つ裂き） | `RepeatVar(1)` と `CalculatedHitCountVar("CalculatedHits")` | 1 + この戦闘で自身が HP ダメージを受けた回数 |
| Flechettes | `CalculatedHitCountVar("CalculatedHits")` | 手札のスキル枚数（0 もあり得る） |

各カードの `OnPlay()` が `WithHitCount(...)` に渡す値と照合した。
取得順は `HitCount` → `CalculatedHits` → `Repeat`。これにより八つ裂きの `Repeat=1` が
実際の回数を隠さなくなる。明示的な回数は 0・1 も `hits` に出し、
`total_damage = damage * hits` と `damage_cap` の計算に同じ値を使う。
回数変数がない札は従来どおり cap 計算上 1 回とする。
ランダム対象の `total_damage` は攻撃全体の打点であり、その敵に全弾当たる保証ではない。

## ゲームの版と schema

`Debug/ReleaseInfoManager.LoadConfig()` は macOS の実行ファイルの隣から
`../Resources/release_info.json` を先に探し、なければ実行ファイルの隣を探す。
その `ReleaseInfo.Version` と `Commit` を共通の `NewStateResult()` で
`game_version`・`game_commit` として出す。未取得なら null。
単独・マルチ・メニュー・早期 return の state に共通で付き、markdown にも表示する。
配布物の版をハードコードしたり、MOD/DLL の assembly version から推測したりしない。

schema は **4 のまま**。`McpMod.StateSchemaVersion` と `docs/raw-full.md` の規則は
既存項目の意味変更・削除時だけ増分である。今回の版情報・購入状況は項目追加、
回数は既存の「攻撃回数」という意味を保つ不具合修正なので増やさない。
MOD 内に dump の `meta.json` を作る処理はない。engine 側で state の
`game_version`・`game_commit` を転記する対応は別変更となる。

## ターン終了の待ち

待機コードの変更は不要と判断した。根拠は次のとおり。

- 新版の `Combat/CombatManager.AfterAllPlayersReadyToEndTurn()` は
  `EndTurnPhaseOne` 設定後、`WaitUntilQueueIsEmptyOrWaitingOnNonPlayerDrivenAction()` を待つ。
  旧版の `ActionExecutor.CurrentlyRunningAction` / `AfterActionExecuted` から、
  `ActionQueueSet.AreAnyPlayerDrivenActionsBeingExecuted()` / `ActionQueueChanged` に変わった。
- `GameActions.Multiplayer/ActionQueueSet` はキューの先頭にある player-driven action を
  選択待ちも含めて検査する。enqueue・pause・resume・完了時に `ActionQueueChanged` を発火する。
  MOD はこのイベントを購読・抑止せず、`ExecuteEndTurn()` で従来どおり
  `ActionQueueSynchronizer.RequestEnqueue(new EndPlayerTurnAction(...))` の経路を使う。
- `Commands/PlayerCmd.EndTurn()` はローカルの終了操作で
  `CombatManager.OnEndedTurnLocally()` を呼び、`PlayerActionsDisabled=true` にする。
  MOD の `AddResolvingState()` は同じ `ActionQueueSet.IsEmpty` と
  `PlayerActionsDisabled`・開始中・終了中・手札プレイ中を観測する。
- `IsSettledState()` は通常戦闘で `is_resolving=false` だけでなく
  `battle.is_play_phase=true` を要求するため、敵の行動の間のキュー空状態で完了しない。
  選択画面は入力境界として返すので、ゲーム側が player-driven action の選択を待っても
  MOD が回答を妨げない。`AppendSettleResult()` のポーリングと sleep は HTTP スレッド上にあり、
  状態取得時だけメインスレッドに処理を渡すのでゲームの await をブロックしない。

これはソース照合であり実機確認ではない。既存の `wait` は timeout と
3 秒の「観測値が変わらない」打ち切りを持つため、完了の絶対保証ではない。
実機では `end_turn` を `wait:true` で送り、通常の敵ターン、
選択待ちを含むターン、戦闘終了で次の入力境界まで進むことを確認する。

## 検証

`tests/V0113CompatContract` は本番の計算・版情報・購入結果ヘルパーをリンクして検証する。
ゲームとの境界はダブルであり、本体のプレビュー処理や通信・UI は実行しない。
調整役は v0.113.0 実機で通常／偽商人の購入、除去の選択とキャンセル、
ポーション売却、上記多段札の `hits`・打点・cap、state の版、ターン終了を確認する。
